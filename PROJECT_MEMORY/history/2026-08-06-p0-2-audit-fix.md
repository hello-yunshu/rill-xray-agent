# P0-2 Audit Fix — Operation WAL, Two-Stage Audit Append, Fault Injection

Date: 2026-08-06

## Summary
Implemented P0-2 (audit reliability and atomic state transitions) on the public repository.

## Changes
- `python/rill_xray_agent/operation.py` (new): OperationLog WAL transaction coordinator. Each
  state-mutating operation writes an intent record (pre/post state hashes, audit event), applies the
  state file, commits an audit event, writes a terminal record, then cleans up. Startup recovery
  (`recover()`) completes, cancels, or flags unresolved operations by comparing state hashes against
  the intent. Fault injection points: `RILL_OP_FAIL_AFTER_OPERATION_INTENT`,
  `RILL_OP_FAIL_AFTER_STATE_COMMIT`, `RILL_OP_FAIL_AFTER_AUDIT_EVENT`,
  `RILL_OP_FAIL_AFTER_OPERATION_TERMINAL`.
- `python/rill_xray_agent/audit.py`: two-stage append (`reserve()` writes an append intent with a
  pre-flight capacity check; `commit_event()` commits the reserved event, idempotently appending when
  absent and discarding stale intents). Capacity exhaustion fails closed before any state change.
  Fault injection: `RILL_AUDIT_IO_ERROR`, `RILL_AUDIT_FAIL_AFTER_EVENT`.
- `python/rill_xray_agent/runtime_service.py`: mode/register/rootResult/feedback now run through the
  operation WAL; idempotent replays produce no duplicate audit events; audit capacity failure leaves
  state unchanged.
- `python/rill_xray_agent/health.py`: accepts the operations log and reports
  `unfinished_operations` / `recovery-required`.
- `python/rill_xray_agent/errors.py`: added `OperationError`.
- `tests/test_operation_atomicity.py` (new): 5 tests covering audit round trips, all four WAL fault
  injection points with crash recovery, audit capacity fail-closed, restart replay, and idempotency.
