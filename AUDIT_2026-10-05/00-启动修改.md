# Rill Xray Agent 启动修改

## 所有项目的启动方式

远程审计文档分支统一为 `audit/2026-10-05`。先 fetch 并切到该分支，再创建独立修复分支；保持用户已有改动，分支切换失败先查看 git status，不能 reset/clean。

```sh
git fetch origin
git switch audit/2026-10-05
```

只看本目录的新合并文件。一次给模型一个任务，任务内它要自主依次完成所有 ID，不需要用户为每个 ID 重新发起。完成后审阅修复记录与测试，再启动下一份。真实 Linux/OpenWrt 资格仍是独立执行环境要求，不是“合并阶段后取消的测试”。

创建修复分支 `fix/audit-rill-agent-safety`，发送：

```
请读取 AUDIT_2026-10-05/00-审计报告与执行顺序.md，完整执行
AUDIT_2026-10-05/01-Rill源头运行与升级安全.md。
你当前在 canonical 源头仓库，按提示词映射修改真实 python/ 和 integration/scripts 源文件；
不要只改 Xray 镜像。按 XRA-01/02/03/04/05 顺序逐项写回归、实现和验收。
保持自动执行权限默认关闭，升级失败不恢复旧 auto 授权，保留历史状态与用户改动。
实际改代码并本地提交，记录 ID→修改→验证→未完成项；不自动合并 main/推送修复/发版。
```

第一任务验收后，继续同一修复分支执行 `02-Rill源头备份与隐私.md`（XRA-07/08/09）。
两个任务完成后运行完整 canonical 资格，生成并验证 canonical manifest/bundle，记录 exact 修复 commit/digest。
然后启动 Xray 的阶段 3，消费该修复提交并做真实 host qualification；源头问题不重复实现。
